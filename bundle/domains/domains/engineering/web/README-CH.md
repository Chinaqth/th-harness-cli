# Web Frontend Engineering Domain 目录说明

本文件帮助中文使用者理解 `engineering.web` Domain Pack 中每个非隐藏生产文件和必需目录的职责及实际行为。英文生产制品是权威契约；本文件只是中文导览，不新增、翻译替代或改变任何规则、权限、承诺、组织事实或生命周期决定。

## 当前状态

- Domain ID 为 `engineering.web`，版本为 `0.1.0`，主 Owner 为 `platform-web`。
- 生命周期状态为 `active`，Owner 与 Reviewer 均为 `platform-web`；激活只授予路由可选资格，不授予部署、生产访问、发布、风险接受或其他操作权限。
- 项目命令与权限、私有架构、浏览器与辅助技术矩阵、可访问性和性能目标、安全基线、发布门禁以及恢复流程仍是项目 Overlay 或任务契约的强制输入。缺失这些输入会阻止相关任务声明和操作，但不会阻止全局 Domain 被路由考虑，也不会把未知事实变成默认值。

## 顶层生产文件

| 路径 | 职责 | 实际行为 |
| --- | --- | --- |
| `DOMAIN.md` | 定义 Web 前端工程的持久专业契约。 | 约束该 Domain 的目标、Owner 边界、范围、稳定输入、证据型输出、交接和失败处置；明确区分前端客户端责任与产品、设计、后端、安全、法律、发布及生产运维的决策权，并将缺失的项目或任务输入保留为受影响声明的 `needs-org-input`。 |
| `domain.json` | 提供可机器读取的 Domain 身份和生命周期清单。 | 声明 `engineering.web@0.1.0`、`active` 状态、`platform-web` Owner、适用任务类型与仓库信号、Kernel 1.0 兼容性，并引用仓库内激活证据。 |
| `owners.json` | 提供可机器读取的所有权记录。 | 将主 Owner 和 Reviewer 均绑定为 `platform-web`；该生命周期审阅身份不授予项目、部署、生产或风险接受权限。 |
| `capabilities.json` | 组装该 Domain 可供选择的专业能力。 | 定义并限定语义界面、ECMAScript 浏览器行为、Web 可访问性、浏览器 HTTP 集成、前端安全验证、浏览器性能可观测性和跨浏览器兼容性七项 Capability；每项均引用现有 Workflow、Skill 和 Evaluator，并明列工具类型、任务范围权限以及需要另行授权的操作。 |
| `routes.json` | 定义任务信号到 Capability 候选项的确定性选择表。 | 按安全、可访问性、兼容性、性能、HTTP、ECMAScript 和语义界面的优先级，匹配明确任务类型与区分性信号后选出已存在的 Capability；路由选择仍受 Capability 权限、项目 Overlay 和任务契约门禁约束。 |
| `README-CH.md` | 提供当前 Domain Pack 的中文完整清单。 | 列出并说明每个非隐藏生产文件和必需目录，同时指向英文权威契约；它不执行路由、验收或授权。 |

## 专业规则

| 路径 | 职责 | 实际行为 |
| --- | --- | --- |
| `rules/` | 容纳 Domain 的规范性专业不变量。 | 为适用的 Web 前端工作提供 Kernel 约束之上的专业规则；项目 Overlay 可以专化或加严，但不得削弱这些规则或 Kernel 红线。 |
| `rules/BASE.md` | 定义必须遵守的 Web 前端工程基线。 | 约束实现者保留原生 HTML 语义，分开规范成熟度与目标支持，对完整体验验证可访问性，遵守 HTTP 契约，把 Origin 和注入内容视为安全边界，先测量后判断性能，按声明矩阵验证兼容性，并始终保持证据与权限边界显式。每条规则都定义必需证据及失败交接。 |

## 交付流程

| 路径 | 职责 | 实际行为 |
| --- | --- | --- |
| `workflows/` | 容纳可重复执行的 Domain 工作流。 | 保存从前置条件、有序步骤到输出、验证、负向路径、恢复与交接的可复现过程。 |
| `workflows/WORKFLOW.md` | 定义框架中立的 Web 前端交付流程。 | 执行输入门禁，然后依次基线化受影响体验、设计最小授权变更、实现语义结构与呈现、实现应用行为、集成 HTTP 边界、验证可访问性和安全隐私边界、测量性能、检验声明矩阵下的兼容性，最后核对证据并产出交付包。每一阶段都规定输出、验证和 fail-closed 响应。 |

## 独立验收

| 路径 | 职责 | 实际行为 |
| --- | --- | --- |
| `evaluators/` | 容纳 Domain 专属的独立验收契约。 | 将实施者的交付与独立 Evaluator 的证据审查和最终行为判定分离，不以验收结果替代组织批准或生命周期变更。 |
| `evaluators/EVALUATOR.md` | 定义 Web 前端交付的独立评估标准。 | 校验评估入口和证据记录，依次验证需求追溯、HTML、CSS、ECMAScript、HTTP、可访问性、前端安全、浏览器性能、跨浏览器行为以及交接恢复；检查证据新鲜度、可复现性、冲突与抖动，按 `P0`–`P3` 归类发现，并根据逐项状态产出 `pass`、`fail` 或 `blocked` 行为判定，同时单独记录 `needs-org-input`。 |

## 执行 Skill

| 路径 | 职责 | 实际行为 |
| --- | --- | --- |
| `skills/` | 容纳 Domain 自有的可调用 Skill。 | 将非显然的专业步骤、证据约束、停止条件和项目 Overlay 边界打包成 Agent 可执行的程序。 |
| `skills/web-interface-delivery/` | 容纳 `web-interface-delivery` 专用 Skill 的完整定义。 | 将该 Skill 的触发范围、执行步骤、证据要求、停止条件与权限边界作为一个可定位的生产目录维护；目录本身不执行、授权或评估交付。 |
| `skills/web-interface-delivery/SKILL.md` | 定义 `web-interface-delivery` Skill 的触发条件和紧凑执行循环。 | 在任务输入完整且已授权时，指导 Agent 建立证据脊柱、展开界面状态矩阵、选择最小平台化设计、按可观测边界实现、分层验证并核对交付包；它执行 `workflows/WORKFLOW.md`且受 `rules/BASE.md` 约束，但不自我评分、部署、批准发布或接受风险。 |

## 输出模板

| 路径 | 职责 | 实际行为 |
| --- | --- | --- |
| `templates/` | 容纳框架中立、可重用的 Domain 输出结构。 | 统一证据型交付制品的字段和索引，由任务契约或项目 Overlay 提供实际事实，不在模板中固化项目命令、目标或权限。 |
| `templates/delivery-evidence.md` | 提供 Web 前端交付证据记录的可填写模板。 | 产出覆盖记录身份、需求与计划证据、环境与修订、基线与变更面、测试案例、各项 Web 工程结果、实际执行过程、发现与严重度、风险与交接、组织缺口、恢复指导及最终证据索引的结构；要求填写者保留失败、跳过、不可用、阻塞、冲突与抖动结果，清理敏感数据，且不得用占位符发明组织事实。 |

## 目录完整性边界

隐藏的 `.gitkeep` 文件只用于保留目录，不是生产制品，因此不列入上述清单。当其他生产文件或必需目录增删时，必须在它们稳定后同步更新本文件，以保持中文清单与英文权威制品一致。
