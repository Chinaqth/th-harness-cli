# {{DISPLAY_NAME}} Domain 目录说明

本文件帮助中文使用者理解 `{{DOMAIN_ID}}` Domain Pack 中各文件和目录的职责。英文生产制品是权威契约；本文件只做中文导览，不新增规则、权限或组织政策。

## 顶层文件

| 路径 | 作用 | 会做什么事情 |
| --- | --- | --- |
| `DOMAIN.md` | 描述 Domain 的目标、边界、输入、输出、Owner 和成熟度。 | 帮助维护者判断该 Domain 负责什么、何时交接，以及当前是否具备使用条件。 |
| `domain.json` | 保存稳定身份、版本、生命周期、适用性、兼容性和激活证据。 | 供注册表校验和未来的路由解析器判断该 Domain 是否兼容、是否允许参与路由。 |
| `routes.json` | 定义任务类型、仓库信号、优先级和候选 Capability。 | 供未来的路由解析器决定哪些任务应考虑这个 Domain；`draft` 状态下不会用于生产路由。 |
| `capabilities.json` | 组装 Workflow、Skill、Tool、Evaluator、权限和依赖。 | 描述被选中的能力需要执行哪些流程、检查哪些结果并依赖哪些其他能力。 |
| `owners.json` | 记录主 Owner 和 Reviewer。 | 确定谁负责专业正确性、谁必须审核重要变更与激活。 |
| `README-CH.md` | 提供当前 Domain 目录的中文导览。 | 逐项解释实际生产文件和目录；不得替代英文权威契约。 |

## 子目录

| 路径 | 作用 | 会做什么事情 |
| --- | --- | --- |
| `rules/` | 保存该专业领域不可违反的规则。 | 在 Kernel 红线之上增加更具体的专业约束，但不能削弱 Kernel。 |
| `rules/BASE.md` | 提供专业规则的注册骨架。 | 等待补全流程用来源支持的具体规则替换占位内容。 |
| `workflows/` | 保存可重复执行的专业工作流。 | 定义前置条件、步骤、输出、验证方式、失败处理和交接。 |
| `workflows/WORKFLOW.md` | 提供专业工作流的注册骨架。 | 等待补全流程定义可执行步骤、检查和失败路径。 |
| `evaluators/` | 保存 Domain 专属验收契约。 | 依据可复现证据判断工作流结果是否通过，并覆盖负向路径。 |
| `evaluators/EVALUATOR.md` | 提供验收契约的注册骨架。 | 等待补全流程定义证据要求、负向场景和通过标准。 |
| `skills/` | 保存 Domain 自有 Skill。 | 为 Agent 提供执行专业工作流所需的非显然指导、参考资料和确定性工具。 |
| `templates/` | 保存可复用的输出模板。 | 统一常见专业制品的结构，不写入项目私有事实。 |

## 完成后的维护要求

当 `$complete-domain-pack` 完成内容生成时，必须根据实际目录重写本文件：列出每个非隐藏生产文件及目录，说明其作用和实际行为，并删除已经不存在的占位说明。
